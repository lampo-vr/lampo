# Audits

This is the ledger of security and consistency audits. It records what was read, at which commit, what it found and
what is still waiting to be read. It exists so that no audit reads the same unchanged code twice and so that no
change goes unread.

- **Areas** split the repository by attack surface. Every tracked file belongs to at least one area
  (`test/unit/audits.test.ts`). Each area records the audit that last read it and the commit it was read at.
- **`node scripts/audits.ts`** prints, for each area, how many commits and files have changed since that area's
  audit. `node scripts/audits.ts <area>` lists the changed files. An audit reads that delta, plus whatever the delta
  touches, and it starts from the queue.
- **Needs audit** is the queue. When a merge changes an area's security surface, the same commit adds one line here:
  new routes or inputs, auth or permission logic, workspace scoping, what review links show, people's data, text that
  reaches agents, media or files from outside, outbound requests, deploy settings. A fix for an audit finding also
  adds a line, so that the next audit checks the fix. The audit that covers a line removes it.
- **Running one:** the `audit` skill (`.claude/skills/audit/`) has the method, the rules for throwaway stores, a
  checklist per area and the report format.
- **Reports:** an audit's work with open findings stays private in `audits/<date>-<id>/` (gitignored): the report,
  one file per area and the repro scripts. It stays there until the findings are fixed or deferred to `ROADMAP.md`;
  then a public summary may follow as `audits/<id>.md`. The log below records counts and outcomes, never exploit
  details.
